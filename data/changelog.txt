LightFTP changelog: v2.3.1 → master (e7daa84, 2026-10-19)
=========================================================

ADDED
-----
- PBKDF2-SHA256 password hashing (src/fcrypt.c). Users can have a hashpswd= record in the form pbkdf2-sha256$iterations$salt$hash, and fftp -p generates one. Sensitive buffers are zeroed after use.
- MODE and STRU commands.
- Optional TLS. The server now starts without a certificate or key. TLS-specific commands are hidden or rejected when TLS isn't configured.
- follow_symlinks option in fftp.conf. It defaults to 0, so symlinks are not followed.
- Symlink escape test script (src/tests/test_symlink_issue72.py).
- Timeout for worker thread cancellation.
- CONTRIBUTING.md, a README table of contents, build badge and ASAN build notes, and VS Code configs.

CHANGED
-------
- Path handling. Every path-using command (LIST, CWD, RETR, STOR, APPE, DELE, MKD, RMD, SIZE, RNFR, RNTO, MLSD, CHMOD) now resolves paths through a new wrapper that rejects symlinked path components when symlinks aren't followed.
- Worker thread ownership. The worker thread is now the sole owner of the data socket and file descriptor. The control thread only calls shutdown() and waits. Shared state uses atomics and a per-client data_lock.
- TLS control replies. For TLS-protected control connections, transfer workers no longer write replies directly, since a GnuTLS session must not be used by two threads at once. Workers hand the reply to the control thread through a wake pipe.
- AUTH rejects a repeated TLS request (503) and is refused while a transfer worker is active. PORT is rejected while a worker is running.
- Command lookup uses binary search instead of a linear scan. The command table is kept sorted.
- TYPE handling updated (#86). TYPE L/E variants and unsupported parameters now return 504, while S/F return 200.
- Stricter input validation:
  - Control bytes: control and NUL bytes are rejected.
  - USER: character checks, including DEL.
  - PORT: digit and delimiter rules.
  - REST: digits only, parsed into an unsigned value.
  - PBSZ: parameter validation.
- Stricter config parsing and validation for IPs, ports, booleans and maxusers. Config and log files are opened with O_CLOEXEC, and zero-length config files are handled.
- STOR I/O errors now map to appropriate reply codes (#81).
- TLS initialization reports explicit success or failure, cleans up after partial init, and honors data_protection_level.
- Sample fftp.conf: no embedded plaintext admin password (the admin user now uses hashpswd), and the file moved to data/.
- Source tree restructured (src/, src/inc/, data/). Types and thread names refactored to lowercase. Makefiles and AppVeyor config updated. README updated with new Windows version support, build and config instructions.
- This changelog reformatted.

FIXED
-----
- Symlink escape (#72). O_NOFOLLOW only protects the last path component, so a symlink in an intermediate directory could escape the FTP root.
- Cross-session data hijack (#74).
- Password check wildcard (#73).
- REST value is now checked before use (#80).
- Connection slot accounting. maxusers is enforced safely under concurrency.
- Race conditions. Worker-thread cleanup races and use-after-close of file descriptors. Also thread-cancel safety and makefile/build script fixes.
- Issues #37 and #44 (commit aaf2710) and #45 and #60 (commit 92861b3).
- Type-cast fix for character checks (#64).
- GCC warnings, and the redundant linux/limits.h includes.

REMOVED
-------
- The LightFTP.sha256 file.
- The old SHA256+Base64 password flow, replaced by PBKDF2.
- The old Source/ and Bin/ layout.
